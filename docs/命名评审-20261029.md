# 飞脑 · 命名评审（任务 5）

> 评审日期：2026-10-29 ｜ 范围：spec.json、backend、frontend、docs 的全部对外命名
> 结论：**1 处已改、3 处建议保留现状、2 处挂起待版本窗口**

## 一、命名资产盘点

| 层 | 命名 | 评价 |
| --- | --- | --- |
| 品牌 | 飞脑（AI Agent 网关） | 主品牌清晰 |
| 子系统 | 飞审（审批）/ 飞忆（记忆）/ 飞构（配置版本化）/ 飞执（Agent 任务） | 统一「飞+单字动词」构词法 |
| 工具 | search_docs / query_system / ingest_doc | snake_case 一致，动词+宾语 |
| 上游 | kms / bi / cc | 全小写缩写一致 |
| 模式 | plan / default / auto / yolo | 与业界惯例对齐 |
| 路由 | /api/{chat,ai,approvals,memory,harness,skills,tasks,...} | 复数/单数混用，见 §三-3 |

## 二、已改（本次生效）

| 项 | 原 | 改 | 理由 |
| --- | --- | --- | --- |
| 前端导航（Agent 任务页） | 飞行 | **飞执** | 「飞行」是名词且语义歧义（航空）；飞字辈是「飞+动词」：飞审=审、飞忆=忆、飞构=构，Agent 执行器应为「飞执」 |

## 三、评审后决定保留现状的

1. **路由 `harness` ↔ 中文「飞构」不直译**——保留。harness 在本项目语境=「配置版本化+证据链」的工程骨架（与 test harness 同源），中文取意译。docs 已有对照说明，改动只会破坏已有文档指向。
2. **`lcm` 路由用缩写**——保留。LCM（Long-Context Management）在后端模块名 `lcm.py`、表名、文档中已全程一致；缩写扩散面太大，收益为零。
3. **路由单复数混用**（`/api/tasks` 复数、`/api/skills` 复数、`/api/memory` 单数）——保留。memory 是资源域不是集合语义；为统一而改路由是纯破坏性变更。

## 四、挂起项（需要版本窗口，暂不动）

1. **`spec.pilots` 键名双义**：`/api` 前端导航「三试点」指 rag/nl2api/script 三个试点功能，而 `spec.pilots`（rag_topk / nl2api_max_rows / react_max_steps）实为**调参**。建议下个大版本把 `pilots` 改名 `tuning`（涉及 spec 校验、读取路径、文档约 5 处）。
2. **`upstreams.cc`**：cc = 呼叫中心（Customer Center），对新人不直白。建议改 `contact_center` 或加 spec 注释；涉及演示桩与文档，随下次上游扩展一起做。

## 五、新命名规范（并入 CONTRIBUTING）

- 子系统中文名：**飞+单字动词**，进前端导航需同时在 `docs` 登记英文名与路由
- 工具/函数：snake_case，动词+宾语；路由：小写、段名与资源表名一致
- 新增配置键：先过一遍「这个词在代码库里有没有第二个意思」（pilots 的教训）
