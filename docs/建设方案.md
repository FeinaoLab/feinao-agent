# 飞脑AI Agent网关 · 建设方案（P0）

> 立项依据：《飞系全系项目AI-Agent集成分析报告-20261026》L3 层主攻方向
> 交付形态：feinao-agent（8060，前缀 /nao/），零依赖 Python+SQLite，与飞系全系同构

## 一、目标
为飞系 51 项目提供统一 AI Agent 入口：统一 LLM 网关（多供应商+降级链+用量看板）、三个试点（知识问答 RAG / BI 智能查数 / 客服话术）、轻量 ReAct 工具调用、全量审计。P0 两周内上线可用。

## 二、架构
```
frontend(对话工作台SPA) / mobile(PWA对话)
        │ /nao/
   nginx 统一入口 → :8060 engine.py(ThreadingHTTPServer)
        ├── ai.py
        │   ├── llm_chat()  LLM 网关：deepseek→hunyuan→mock 降级链
        │   │               用量落库 usage 表（延迟/成败/token）
        │   ├── rag_*()     SQLite FTS5 检索（LIKE 兜底），docs/docs_fts
        │   ├── pilot_ask()        试点1：RAG 问答（带引用）
        │   ├── pilot_nl2api()     试点2：意图→实体匹配→上游REST→LLM总结
        │   ├── pilot_script()     试点3：五段式客服话术
        │   ├── react_run()        L2：工具注册表+步数上限
        │   └── upstream_*()  上游系统客户端（登录缓存+spec驱动实体发现）
        └── SQLite: users/conversations/messages/audit/usage/docs
```

## 三、关键设计决策
1. **NL2API 而非 NL2SQL**：LLM 只产出"实体+搜索词"意图（或 spec 关键词直接匹配），数据一律走上游 REST API 白名单——天然防 SQL 注入，且复用三角色权限
2. **spec 驱动实体发现**：上游实体列表实时从 /api/spec 拉取（兼容二批 entities 与电商 tables 两种形态），新增系统零代码接入
3. **mock 供应商兜底**：无 Key 环境全链路可用（测试/演示），生产配 Key 即切真实模型，代码零改动
4. **审计优先**：所有 AI/工具调用写 audit 表（谁/何时/什么工具/什么参数/什么结果/成败），viewer 角色不可见
5. **零依赖底线**：FTS5 是 SQLite 自带模块；无 Redis/向量库/Agent 框架

## 四、API 面
| 路由 | 说明 |
|---|---|
| POST /api/login | 三角色登录 |
| GET /api/dashboard | 会话/消息/审计/文档计数 + LLM 成败 |
| POST /api/ai/ask | 试点1 知识问答（RAG+引用） |
| POST /api/ai/nl2api | 试点2 智能查数（system: bi/kms/cc） |
| POST /api/ai/script | 试点3 客服话术 |
| POST /api/chat | 自由对话（会话落库） |
| POST /api/ai/react | L2 ReAct 工具调用 |
| POST /api/rag/ingest · /api/rag/search | 知识入库/检索 |
| GET /api/audit | 审计（admin/ops） |

## 五、风险与对策
- LLM 幻觉 → RAG 强制引用来源；查数结论附真实行数与样本
- 注入 → NL2API 白名单意图；工具注册表封闭集合
- 成本 → usage 表全量计量；mock 兜底供开发
- 断供 → ≥2 真实供应商 + mock 三级降级链
