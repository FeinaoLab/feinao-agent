## 机制说明

1. **原文先落库**：每轮消息无条件写 `lcm_msg`，不因为压缩而删除。
2. **压缩成节点**：超出热区（默认最近 8 轮）的原文按块压成摘要节点，摘要要求保留数字、人名、日期、编号。
3. **节点可上卷**：节点太多时把最老的几个合并成上层节点，形成 DAG，越久远的信息层级越高、越浓缩。
4. **组装上下文**：高层摘要 + 热区原文，超预算就继续压，直到塞进预算。
5. **回溯**：摘要抹掉的细节，用关键词（中文 bigram）在原文里检索补回——这是「不丢细节」的兜底。
