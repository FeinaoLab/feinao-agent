# 飞审审批工作台 · 上线说明

> 项目名：**飞审审批工作台**（飞脑 v1.4）
> 日期：2026-10-27
> 定位：Harness 第 4 层（Permission）的真闸门 —— `requires_confirm` 从「挂起 + 告知」升级为「挂起 → 人工放行 → 系统真执行 → 任务自动续跑」。

## 一、解决什么问题

v1.3 里 `requires_confirm=true` 的动作只会落一条 `pending` 步骤然后被跳过——模型知道"要人确认"，但没有人能确认。飞审补上这一跳：

```
模型要执行写操作（ingest_doc 等 requires_confirm=true 的动作）
   ↓ 不执行，落审批单 + 任务置 waiting_approval
审批人在「飞审」页看到单据（工具/参数/发起人/任务目标）
   ├─ 放行 → 系统真执行该动作 → 结果落 tool_result → 任务交回模型续跑 → done
   └─ 拒绝 → 动作不执行，拒绝理由落 denied 步骤喂回模型 → 任务继续
```

原则：**放行的是"挂起的那一次具体动作"，不是给模型一张空白通行证。**

## 二、能力清单

| 能力 | 说明 |
|---|---|
| 审批单落库 | `approvals` 表：tool/args/发起人/任务/状态/决策人/note/执行结果，全程留痕 |
| 挂起语义 | 写操作触发即挂起：任务置 `waiting_approval`，动作零执行 |
| 放行即执行 | admin 点「放行并执行」→ 系统执行**该次**动作（仍过角色+预算检查，越线审批单退回） |
| 拒绝即拦截 | 不执行，理由落 `denied` 步骤回给模型 |
| 重复提交防扰 | 同一任务里被拒绝过的相同动作，模型再提直接拒，不再挂新单 |
| 幂等回放 | 同一任务里已放行执行过的相同动作，模型重复要时复用结果（不重复落库、不占预算） |
| 审批权隔离 | `spec.json approval.approvers`（默认 admin）；非审批人 403；可配 `allow_self=false` 禁止自批 |
| 超时自动过期 | pending 超 `ttl_minutes`（默认 24h）自动置 expired |
| 工作台 UI | 「飞审」页：待审批/已放行/已拒绝/全部 四个页签，单据卡片含参数 JSON 与放行/拒绝按钮 |
| 仪表盘 | KPI 新增「待审批」计数 |

## 三、接口

| 接口 | 说明 |
|---|---|
| `GET /api/approvals?status=pending\|approved\|rejected\|expired\|all` | 审批人看全部，其他人只看自己发起的；带 `brand=飞审审批工作台` |
| `POST /api/approvals/decide {id, decision: approved\|rejected, note?}` | 决策入口；放行会同步执行动作并返回续跑结果 `run`；错误码 403（无权）/404/409（已处理） |
| `POST /api/ai/react` | 返回新增 `status: waiting_approval` + `approval_id` |
| `GET /api/tasks`、`/api/tasks/detail` | 任务状态新增 `waiting_approval`；步骤 kind 新增 `replay` |

## 四、写操作工具（首个审批对象）

`ingest_doc`：Agent 把内容写入飞脑知识库（roles: admin/ops，单任务 1 次，requires_confirm: true）。
新增写操作时只需在 `spec.json tool_policies` 加 `requires_confirm: true`，自动纳入飞审。

## 五、验证记录

**本地**：`tests/test_approval.py` 7 例 + `test_api.py` HTTP 契约 4 断言，全套 24 例全绿。

| 用例 | 验证点 |
|---|---|
| test_suspend_creates_approval | 挂起生成审批单、任务 waiting_approval、知识库零写入、挂起任务不可绕过续跑 |
| test_approve_executes_and_resumes | 放行真执行（doc 落库恰好 1 篇）、任务续跑 done、证据落库、二次决策 409 |
| test_reject_blocks_execution | 拒绝零执行、理由留痕、任务继续跑完 |
| test_approver_permission | ops 无审批权且状态不变；viewer 被角色拦在审批之前 |
| test_replay_no_duplicate_side_effect | 放行后重复要同一动作：幂等回放，只落库一次 |
| test_repeated_after_reject_not_resubmitted | 拒绝后重复提交直接拒，不再挂新单 |
| test_list_and_expire | 列表带任务目标；ttl=0 时 pending 自动 expired |

**线上（真模型 qwen-flash，公网验收 2026-10-27）**：

1. React 任务要求写知识库 → `waiting_approval`，审批单 #N 生成，知识库命中 0（真执行被挡住）
2. 待审批列表含该单，带完整 args 与任务目标
3. ops01 决策 → **403「角色 ops 无审批权（审批人：admin）」**
4. admin 放行 → `result={"doc_id":3}`，知识库命中 1，任务步骤 `pending→tool_call→tool_result→answer` 状态 done；重复处理 → 409
5. 拒绝路径（唯一标记 ZQ7K9REJECT）→ 拒绝后命中 0，步骤 `pending→denied→denied→answer`，无 tool_call
6. **浏览器实点**：Playwright 登录 → 飞审页渲染（无 JS 报错）→ 点「放行并执行」→ 审批单 #1 `consumed=1, doc_id=4`，task4 done

## 六、部署与坑

- 部署走云端 SSH 中继（本机 22 出口被拦）。中继由 ssh2 npm 依赖改为**零依赖版**（系统 ssh/scp）——此前 npm 装不上会导致服务起不来（端口不监听），重写后启动只依赖 node 本体。
- 前端顺手修了一个历史布局 bug：`.lg-wrap` 的 `display:flex` 覆盖了 `hidden` 属性，登录后登录框仍占顶部；加 `[hidden]{display:none!important}` 修复。

## 七、已知边界（下一步）

- `allow_self=true`（admin 可批自己发起的单）——要职责分离时改配置即可，暂无第二审批人账号
- 审批只有单条决策，无批量操作/委托
- 预算仍是单任务口径，未与审批联动为「按天配额」
- 放行执行是同步的：动作执行 + 续跑在一次请求内完成，长动作需改异步
