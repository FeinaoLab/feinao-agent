## 为什么补这三层

对照表结论：飞脑有循环但 Harness 不完整。Context（LCM）刚补上，State 半空白，
Permission 只有角色级，Verification 只有话术（VERIFY_TAIL）没有环境证据。
按性价比排：证据链 → 动作级权限/预算 → 任务进度。

## 一、证据链（Verification & Evidence）

原则：**验证必须是环境的，不能是模型自述**。所以证据由代码记录"实际发生了什么"，
与模型说了什么互相独立，事后可审计比对。

- 新表 `evidence`：`ts/conv_id/user/channel/q/answer/provider/sources/trace/context_tokens/unverified`
  - `sources`：真实命中的文档 id 或回溯到的会话轮次
  - `trace`：工具调用链 / 摘要与轮次统计
  - `unverified`：回答里是否出现"未验证"标记（VERIFY_TAIL 的落地信号）
- 落库点：`pilot_ask`（channel=rag）、`lcm.ask`（channel=lcm）、`react_run`（channel=react）
- 接口：
  - `POST /api/chat`、`/api/ai/ask`、`/api/ai/react` 响应新增 `evidence_id`
  - `GET /api/evidence?conv_id=N` 按会话查证据链
- `GET /api/dashboard` 计数新增「证据」

实测（线上，真模型 qwen-flash）：
```
chat -> evidence_id=1, channel=lcm, ctx_tokens=159, unverified=1
```
unverified=1 是正确行为：那一轮回答确实带了"未验证"声明，不是缺陷。

## 二、动作级权限 / 预算（Permission）

`spec.json` 新增 `tool_policies`，按"动作"而不是按"人"授权：

```json
"tool_policies": {
  "search_docs":  {"max_calls_per_run": 3, "roles": ["admin","ops","viewer"], "requires_confirm": false},
  "query_system": {"max_calls_per_run": 2, "roles": ["admin","ops"],          "requires_confirm": false}
}
```

执行链（`react_run`）：

1. 角色校验：`user_role(user)` 不在 `roles` 里 → 拒绝，理由喂回模型
2. 预算校验：本次任务已用次数 ≥ `max_calls_per_run` → 拒绝
3. 确认校验：`requires_confirm=true` → 不执行，落 `pending` 步骤等人工
4. 通过 → 计数 +1（**执行前计数**，失败也消耗预算，避免"报错就白嫖"）

拒绝不是静默失败：写入 `trace` 与 `task_steps(kind=denied)`，并在回答里说明原因。

线上实测：
```
viewer 调 query_system ->
"角色 viewer 无权调用 query_system（允许：admin,ops）"
回答：…依据：系统返回错误信息「…」（来源：系统权限校验接口返回）。未验证部分：kms 数据内容…
```

## 三、任务进度落库（State）

- 新表 `tasks(id,user,goal,status,created,updated)`、`task_steps(id,task_id,idx,kind,content,created)`
- `kind`：`tool_call` / `tool_result` / `denied` / `pending` / `error` / `answer`
- 步数耗尽 → 任务保持 `active`，回答里带 `task_id` 提示可续跑；正常结束 → `done`
- `POST /api/ai/react {task_id}`：带历史步骤续跑（旧步骤的工具调用计入本轮预算），
  校验归属与状态，他人任务或已完成任务拒绝续跑
- 查询：`GET /api/tasks`、`GET /api/tasks/detail?id=N`

线上实测：`task 1 -> detail done, kinds=[tool_call, tool_result, answer]`。
