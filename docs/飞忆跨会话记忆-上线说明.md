# 飞忆 · 跨会话长期记忆 上线说明（飞脑 v1.5）

日期：2026-10-27　|　模块：`backend/memory.py`（新增）　|　状态：已上线公网，真模型验收通过

## 1. 定位：Harness 五层对照的最后一块

| 层 | 之前 | 现在 |
|---|---|---|
| 1 Context | LCM 管「一个会话内不丢细节」 | **飞忆**管「换个会话还记得你」：只存提炼条目，不存原文 |

与 LCM 的分工：LCM = 会话内（原文全留 + 摘要上卷 + 回溯）；飞忆 = 跨会话（`memory` 表，检索注入）。

## 2. 三条铁律（防「错记被固化」）

1. **只读检索**：记忆只作参考注入 system，不改写本轮事实；提示词明确「与本轮用户明示冲突以本轮为准」。
2. **默认待确认**：抽取条目一律 `pending`，人点头（activate）才生效；`auto_activate_min` 默认 1.0（永不自动生效），调低才放开。
3. **全程可溯源可撤销**：每条带 `src_conv`（来源会话）+ 时间 + 置信度 + 命中次数；可停用、可删除，本人口=admin 外不可动。

## 3. 数据流

```
对话（LCM 链路）→ memory/extract：LLM 抽条目（JSON）→ 三道过滤 → memory 表（pending）
                     ├─ ① grounding 反虚构：数字必须原文出现过、关键词六成可溯源
                     ├─ ② NOISE 过滤：「已记录/已同步/上下文」等过程性元信息不进记忆
                     └─ ③ 去重 + 新值取代：同位置数值更新 → 旧条目自动停用（auto:superseded）
人工在「飞忆」页点头 → active
新会话提问 → search（关键词打分，只查 active）→ top3 注入 system，带 M#编号/日期/来源会话
         → 回答须标注引用的记忆编号；命中不到就不注入（不占预算、不诱导编造）
每次使用 → evidence.trace.memory 记录本轮用了哪几条 → 事后可对账
```

检索关键词（`_kws`）：中文二元组 + ≥3 字符英文词 + 完整数字；**丢弃 2 字符 ASCII 片段**（"ro" 会误命中 role，线上实测踩过）。

## 4. 接口

| 接口 | 说明 |
|---|---|
| `GET /api/memory?status=pending\|active\|disabled\|all` | 列表 + counts + 注入上限 |
| `POST /api/memory/decide {id, action: activate\|disable\|delete}` | 放行/停用/删除（他人记忆 403） |
| `POST /api/memory/extract {conv_id?}` | 从最近会话抽取（缺省取本人最新会话） |

Dashboard 新增「记忆（生效）/待确认记忆」计数；前端新增「飞忆」页（待确认/已生效/已停用/全部四页签 + 从最近会话抽取按钮）；对话气泡显示 `跨会话记忆 M#x` 或「未命中」。

## 6. 已知边界

- 检索是关键词打分（bigram），不是语义检索——换个说法太多可能漏命中；语料大了再考虑向量库
- 抽取靠手动点「从最近会话抽取」（或 API），未挂自动定时
- `requires` 审批工作台只管写操作，记忆的确认在飞忆页，两处闸门独立
- 记忆按用户隔离，admin 也只能看自己的（list 默认本人）；如需管理员跨用户视图要另开接口
