# 开源化上线说明（v1.6）

> 版本：v1.6 ｜ 日期：2026-10-27 ｜ 仓库：https://github.com/dukema81/feinao-agent（public）

## 目标

把「别人 clone 下来能不能用」这件事做完。此前仓库是 public 的，但内容是内部视角：
三个试点依赖内网上游、没有 LICENSE、没有 CI、README 全中文且以"飞系 52 号项目"开头——
外部读者 clone 后跑不起来，也看不懂它和别的 agent 框架有什么区别。

## 做了什么

### 1. 演示自足化（backend/demo.py）
- 内置假上游，监听 `:8099`，与真实上游同一套契约：`POST api/login`、`GET api/spec`、
  `GET api/<entity>?limit=&q=`；数据为确定性常量（订单 12 / 客户 7 / 知识文章 7 / 工单 6）
- 9 篇种子知识文档，首次启动灌入、幂等；RAG / 话术 / 查数三个试点开箱即有数据
- `FEINAO_DEMO=1`（默认）时随服务启动；`=0` 走 `spec.json` 每个 upstream 的 `base`
- `FEINAO_UPSTREAM_<NAME>` 环境变量覆盖上游地址，优先级最高（演示 → 生产的切换路径）
- 启动横幅说明当前模式；仍在用出厂口令时打印 `[warn] default password in use`
- 出厂口令支持 `FEINAO_PASS_ADMIN` 等环境变量覆盖（仅对新建库生效）

### 2. 开源必备文件
- `LICENSE`（MIT）
- `SECURITY.md`：部署前必查（改口令 / 勿裸暴露 :8060 / FEINAO_DEMO=0）+ 已知设计取舍（token 在内存、无字段级 RBAC、无 SSRF 白名单）+ 漏洞上报渠道
- `CONTRIBUTING.md`：什么改动容易被接受（更硬的证据、更严的闸门、修 bug），什么不会被接受（新依赖、前端构建链、"更自动但不可验证"）
- `.github/workflows/ci.yml`：Python 3.9 / 3.11 / 3.13 跑全套测试 + 一个**不装任何依赖**的 clone-and-run 冒烟 job（起服务 → health → 假上游登录 → 带引用问答断言）——零依赖是主张，CI 负责证明
- `.gitattributes` 统一行尾 LF；`.gitignore` 补 `.env` / `.pytest_cache` / `*.b64`
- 文档里的真实主机 IP 脱敏为 `<your-host>`

### 3. README
- `README.md` 英文首屏：一句话定位（audit-first agent gateway）、三条命令、
  "生产会坏什么 × 本仓库怎么做"对照表、LCM 实测数据表、架构图、能力/端点表
- `README.zh-CN.md` 中文完整版
- 两张实拍图：知识问答（mock 也能出引用）、审批工作台（待审批单带工具/参数/发起人/任务目标）

### 4. 顺手修掉的演示级 bug（都是"别人第一次打开就会撞上"的）
| 问题 | 修复 |
| --- | --- |
| mock 的 RAG 回答写「已检索 0 条」，实际有命中 | 如实报告依据了几条、哪几篇；未命中直接说不知道 |

## 生产部署注意（已处理，2026-10-27 20:30）
开源版 v1.6 起 `FEINAO_DEMO` 默认 1，发布新代码前线上 `.env` 必须显式写 `FEINAO_DEMO=0`，
否则 demo 默认开启，网关会去连 :8099 的假上游而不是真实飞知/飞瞰/飞音。

**已提前写进线上 `/opt/feinao-agent/.env`**（备份 `.env.bak.20261027`），只改配置未重启，
对当前在跑的服务无影响；下次重启/部署新代码时自动生效。线上代码此刻仍是 v1.5（无 `demo.py`），
所以提前加这一行不会造成任何行为变化。

验证：`systemctl show fei-feinao-agent -p WorkingDirectory` → `/opt/feinao-agent/backend`，
`ai._load_env_file()` 在 import 时读上级目录 `.env`，因此重启即生效。
